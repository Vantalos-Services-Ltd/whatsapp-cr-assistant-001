# Explainability Layer - Steps F & G Implementation Summary

## Step F: Timeline Event Integration ✅

### Changes Made

**File: `src/workers/inboundWorker.ts` (lines 1067-1111)**

Updated the `AI_SUGGESTION_CREATED` timeline event to include safe explainability fields:

1. **Added safe explainability data extraction:**
   - `riskLevel`: From `explainability.riskLevel` (preferred) or `proposedAction.riskLevel` (fallback)
   - `rationaleFirst`: First bullet from `explainability.rationale` array (only first item, no full arrays)
   - `missingInfoFirst`: First item from `explainability.missingInfo` array (only first item, no full arrays)

2. **Safety rules:**
   - Only includes first items from arrays (no full arrays stored in timeline)
   - Falls back to `proposedAction.riskLevel` if explainability not available
   - Non-blocking: Timeline event creation failures are logged but don't stop task creation

### Timeline Event Data Structure

```typescript
{
  intent: string,
  risk: string, // Legacy field for backward compatibility
  suggestedTaskType: string | null,
  riskLevel: "LOW" | "MEDIUM" | "HIGH", // From explainability
  rationaleFirst: string | undefined, // First rationale bullet only
  missingInfoFirst: string | undefined, // First missingInfo item only
}
```

**Example timeline event data:**
```json
{
  "intent": "LOOKING_FOR_WORK",
  "risk": "LOW",
  "suggestedTaskType": null,
  "riskLevel": "LOW",
  "rationaleFirst": "Candidate is looking for work",
  "missingInfoFirst": "CSCS card status"
}
```
